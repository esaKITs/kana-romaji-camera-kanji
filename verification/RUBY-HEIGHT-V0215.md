# v0.2.15 shared ruby-height display policy (PP mode)

Keep the source body bottom and source anchor fixed. Measure (body top - ruby top) / body height for geometrically unambiguous ruby-parent regions. Take one maximum observation per parent and the median across parents, so one observed parent suffices to calibrate the image. Apply the shared ratio to all converted PP labels, including Han without detected ruby. With no observation, default to an upward extension of 0.5 body height. Add 0.1 body height as cover margin; paired ruby may require a taller extension than the shared median.

Associations require the original ruby classifier's parentText plus a unique nearby overlapping source parent; display stitching preserves the original source contributors. Only annotations of actually converted Han/number regions are eligible for erasure. Raw OCR text, measured regions, classifiers, reading decisions and supplemental single-character detection remain unchanged. Unknown or ambiguous annotations stay protected.

Labels exclude their own attached ruby from layout blockers. The nearest preceding body/other protected text limits the top at its bottom plus a small safety gap. Source masks use that clamped top across the full measured source/ruby width. If an attached ruby cannot be fully covered without crossing prior text, retain the whole annotation. Ownership uses line IDs, not arbitrary glyph containment inside a union rectangle. Latin ink is vertically scaled to the available taller rectangle using measured ascent/descent; width is not stretched. Crowded labels retain the previous font-size fallback. Background color is sampled from the body rather than the combined body/ruby envelope. Meiki keeps its existing behavior.

Synthetic regressions: one observed ruby propagates to another Han label; no-ruby fallback expands upward; attached ruby is completely erased while a prior body row remains pixel-identical; a blocked ruby is preserved whole; ambiguous ownership remains protected; unconverted Han retains ruby while still supplying geometry calibration. Original mask, font, OCR, reading and Meiki regressions remain enabled.

Practice A: 66 canonical raw / 63 classified regions and three supplemental shi unchanged. Seven observed parents supply a median upward ratio of 0.9. Eight attached ruby regions are completely covered, including the single か and じ. 44 labels, zero layout omissions. Actual mask audit checks full parent-background coverage of all eight ruby boxes, zero residual body ink and zero changes to unreplaced regions. Browser tests repeat ruby coverage in all three display modes and verify canonical parity, readings, synthetic Live and Live-to-Still capture. Measured values are in ruby-height-v0215.json.

The ratio is an implementation parameter derived from each image, not a previously agreed fixed percentage. The no-ruby fallback reuses the earlier 50% headroom baseline. Real iPhone capture is distinct from the synthetic browser stream.

Local validation: 121 unit tests and complete browser comparison passed, including ruby coverage in all three modes. The partial-mode bridge now aligns a literal kana prefix plus Han from the existing dictionary reading, so a token such as お茶 can retain お and convert 茶 without guessed character coordinates. Default-mode readings are unchanged.

The actual mask test also checks a ground-truth region above 食べ: its undetected た annotation has 53 source-ink samples and zero remaining samples after masking, demonstrating propagation beyond explicitly detected ruby. This is a test-image coordinate only, not a production lookup.
