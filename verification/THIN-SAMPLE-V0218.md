# v0.2.18: restore the original five-line sample

## Reproduction

The unchanged public sample `fixtures/numeric.png` is generated by the existing
pinned Noto font and original fixture script. No font weight, text, image size,
or model settings were changed to make this test pass.

Meiki reads all five source lines correctly. Canonical PP, including the archived
21a0546 experiment, produces:

* 三本… → 一本…
* 二十日間休みます。 → 士日間みます
* 十分に注意… → 七分に注意…
* 水が十三杯あります。 → 水か士ー杯めります

The detector boxes are only 24–27px tall, versus the independently measured
47–51px Meiki regions. Using those measured regions in the same PP recognizer
restores all five complete source lines, at both existing crop margins 0 and .12.
The minimum PP emission scores range from .9526 to .9999. They are model scores,
not calibrated recognition-accuracy percentages.

## Implementation

Canonical PP functions, 960px/150px detection, 48px recognition, models, dictionary,
thresholds and source resolution remain unchanged. `ppocr-single.mjs` exports its
existing region-recognition helper; its implementation is not rewritten.

A separate verifier scans with the unchanged Meiki pipeline, associates unique
measured regions with potentially clipped PP body regions (height ratio 1.25–3,
mutual horizontal overlap >=.8), and refuses intersections with any other PP
region, including ruby. Already-agreeing text and its coordinates remain unchanged.

A candidate is accepted only when Meiki text and two PP crop recognitions agree,
and both PP scores meet the existing supplemental .85 gate. Meiki text alone,
only one agreeing PP crop, low PP scores and ambiguous geometry cannot overwrite
PP. Accepted text comes from PP, using the independently measured region.

`rawRegions`, `classifiedRegions` and `primarySnapshot` preserve the canonical
result. `extendedRegions`, `snapshot.lines` and `effectiveText` expose the result
used for reading/display; each repair retains its canonical text/box and vote
records in `geometryVerification`. No guessed per-character coordinates are added.
All work stays in browser workers/on-device memory. PP mode now also downloads
Meiki assets and spends extra time on verification (about 10.3 seconds extra
for Practice A in the local Chromium run; this is not a mobile timing claim). Still mode changes reuse the
cached verified snapshot. Live remains exclusive/asynchronous. If verification
is unavailable, canonical PP is retained and the UI says `text check unavailable`.

## Validation

The dedicated browser test requires exact equality for all five source lines and
all five complete romaji labels, not just counts. It exercises unchanged Meiki,
canonical archive parity, three reading modes, synthetic Live and capture to Still.
Unit tests protect canonical data, independent measured coordinates, multi-pass
agreement, score gates, ambiguity and neighboring ruby.

Practice A must retain identical canonical raw/classified/supplemental regions,
with zero verifier replacements, all 44 labels and all 8 ruby masks intact. The
existing Meiki sample/textbook and numeric-counter browser tests remain enabled.
The full Actions suite runs all 133 tests, including pinned Sudachi assets; local
execution lacks the pruned research assets and passes the other 132 tests.

This restores the reported sample regression; it does not guarantee recognition
of every thin font. Unsupported geometry or disagreements retain the original
PP result. Physical iPhone Live, rotation, vertical text and the separate display/
long-vowel/nasal policy work are not claimed as fixed here.
